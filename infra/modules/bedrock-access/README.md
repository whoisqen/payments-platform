# bedrock-access

Bedrock access for the CI pull-request review and the admin AI agent, in shared-services.

- Review role (`ai.review_role_name`): GitHub OIDC trust pinned to `repo:<org>/<repo>:environment:<review_github_environment>` (default `ai-review`; the review job must declare `environment: ai-review`, and the environment's protection rules are part of the gate) and audience `sts.amazonaws.com`; `InvokeModel*` only on the inference profile and, through it, on its foundation models in `profile_regions`; 1 hour. Output `review_role_arn` goes to the repository variable `AI_REVIEW_ROLE_ARN`.
- Admin-agent role: assumed only by `admin_principal_arns`, which must be IAM Identity Center role patterns (`arn:aws:iam::<acct>:role/aws-reserved/sso.amazonaws.com/*/AWSReservedSSO_<PermissionSet>_*`); a bare `role/*` or a plain role fails validation. Optional `admin_principal_tag` is checked as `aws:PrincipalTag/<key>`. `aws:MultiFactorAuthPresent` is absent from Identity Center sessions, so `admin_require_mfa` defaults to false; MFA is enforced at the IdP (Okta). Set it true only for principals with an IAM MFA device.
- Admin permissions: invokes only `admin_allowed_model_arns`, and only through the endpoint (`Deny bedrock:Invoke*` unless `aws:SourceVpce` is the endpoint id); reads named log groups and metrics; explicit deny on writes, secrets, KMS, CDE-account logs (unless `cde_logs_allowed`) and any action outside the allow list. No admin role while `admin_principal_arns` is empty.
- The CI review role cannot carry the `aws:SourceVpce` condition: GitHub-hosted runners are outside the VPC and reach Bedrock over the public endpoint. The review role is limited by the OIDC trust, the guardrail condition and the model list only. Self-hosted runners in the VPC would allow it.
- Guardrail: `aws_bedrock_guardrail` blocks card number, CVV and AWS access keys (input and output) and filters prompt attacks at HIGH; a numbered version is published. Both roles may invoke only with `bedrock:GuardrailIdentifier` = guardrail ARN plus that version, so callers must pass `guardrailIdentifier` and `guardrailVersion` (outputs `guardrail_id`, `guardrail_version`).
- CDE accounts: `cde_account_ids` is required and not empty. Logs and CloudWatch of those accounts are denied by ARN. `cloudwatch:GetMetricData` and `oam:*` have no resource ARN, so their deny uses `aws:ResourceAccount`, which applies only where the service sets the key; it is a backstop. The real control is to create no OAM link or sink policy that exposes a CDE account to shared-services. `GetQueryResults` and `GetMetricData` take `Resource: *`.
- Data residency: `inference_profile_id` must start with `eu.`, `region`, `profile_regions` and admin model ARNs must be `eu-*`. Output `eu_only_scp_policy_json` is a service control policy document (deny `bedrock:Invoke*` outside `eu-*`); the organization stack attaches it, this module does not. The profile's destination regions must all be EU for the SCP not to break it.
- Endpoint: `bedrock-runtime` interface endpoint with private DNS; its policy admits the two roles and their models; 443 from `endpoint_allowed_cidrs` only.
- Invocation logging is off; `invocation_logging_enabled` creates an S3 bucket (KMS, 30 day expiry, text only) tagged `pci-scope=connected`. The bucket policy denies `s3:GetObject` to everyone except `invocation_log_audit_role_arn`; server access logs go to `invocation_log_access_log_bucket`; `invocation_log_object_lock` (GOVERNANCE or COMPLIANCE, days) is optional, and COMPLIANCE cannot be undone. The KMS key policy must allow `bedrock.amazonaws.com` and the audit role.
- Denial of wallet: `aws_budgets_budget` (`budget_monthly_usd`, default 200; alerts at 80 percent actual and 100 percent forecast to `budget_subscriber_emails` or `budget_sns_topic_arns`) and one CloudWatch alarm on `InputTokenCount` (Sum per hour, `input_token_alarm_threshold`) per ModelId (the profile and the admin models). The metric has no role dimension, so a per-role alarm is not possible. Check which service names Bedrock charges appear under in Cost Explorer and set `budget_service_names`. Neither the budget nor the alarm stops calls: lowering the Bedrock service quotas (tokens and requests per minute of the model, Service Quotas console or support case) is a manual step that is not in Terraform.
