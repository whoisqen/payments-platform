# live

Terragrunt stacks: `<env>/<region>[/<cell>]/<component>/terragrunt.hcl`; environment, region, cell and component come from the path, the account from `<env>/env.hcl`.
`terragrunt.hcl` holds the S3 state (`use_lockfile`, KMS, `<env>/` prefix), the generated provider with `default_tags` of section 22 and the shared inputs.
`_envcommon/<group>/<component>.hcl` holds the module source and the settings every stack of a component shares.
eu-central-1 is the only writing region (cells `cell-0` to `cell-3` and `spare`, each with its own cluster and data stores, plus the shared locker Aurora).
us-east-1 is a warm standby in environments with `standby_enabled` (stage): per cell eks, karpenter, memorydb, iam-workloads and Aurora readers, its own egress path (`egress-vpc`, `firewall`, `tgw`), plus routing from `edge-dns-routing`. us-east-2 holds only non-compute resources: VPC, KMS replica keys, ECR replicas and headless Aurora secondaries; DynamoDB, S3 and secrets replicas and backup vaults are owned by the eu-central-1 stacks.
First apply of an environment: `tgw`, then set `transit_gateway_id` in `env.hcl` (stage: the region's entry of `deploy.stage.transit_gateway_ids` in `config/platform.yaml`) so that `vpc` routes through it.
Sizes come from `config/environments`: `prod.yaml` is the reference, `stage.yaml` repeats it (production size and topology on Spot nodes for the payments and stateful pools) and `dev.yaml` lists what dev lowers. `env.hcl` merges the file of its environment over `prod.yaml` one level deep. `prod` mirrors `stage` in one account with its own network and zone from `config/platform.yaml`; its node pools never use Spot. `cde-prod` is not a separate account yet: the CDE pool of each cluster is never Spot in any environment.
Analytics (outside the CDE) lives in `<env>/eu-central-1/analytics/`: its own cluster (`eks`, `karpenter`) for ClickHouse, `msk`, `opensearch`, `clickhouse` and the security groups `msk-access` (cell and analytics nodes) and `opensearch-access` (analytics nodes); cell `iam-workloads` attach the MSK producer policy. `ci-oidc-roles` holds the GitHub OIDC plan role of each account (and the ECR read role in shared-services).
