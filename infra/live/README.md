# live

Terragrunt stacks: `<env>/<region>[/<cell>]/<component>/terragrunt.hcl`; environment, region, cell and component come from the path, the account from `<env>/env.hcl`.
`terragrunt.hcl` holds the S3 state (bucket and key of the root from `infra/bootstrap`, `use_lockfile`), the generated provider (assumes `<prefix>-<env>-tf-exec`; `PAY_TF_DIRECT=true` uses the caller's credentials) with `default_tags` of section 22 and the shared inputs.
`_envcommon/<group>/<component>.hcl` holds the module source and the settings every stack of a component shares.
eu-central-1 is the only writing region: cells `cell-0` to `cell-3` and `spare` (own cluster and data stores each) and the shared clusters `locker` (card vault, its Aurora and `endpoint`, the internal NLB `locker.payments.svc.locker.<cluster_domain>`), `edge` and `control-center` (`_envcommon/shared-clusters`). Next to every `eks` unit an `argocd-registration` unit writes `<prefix>/argocd/clusters/<name>` into shared-services. Vault runs once, in `shared-services/eu-central-1/vault` on the central cluster, and serves every environment. `cell-migration` holds the SSM documents of `scripts/cells/migrate-merchant.py`; dev runs `cell-0` and `spare` only, stops its Aurora clusters outside the working window (`aurora-schedule`) and keeps just the edge (`panel-edge`, `waf-edge`, `kms`) in us-east-1.
Only prod has a standby region: us-east-1 is a hot standby that runs all the time at the working size (cells, spare and the locker, edge and control-center clusters, its own egress path `egress-vpc`, `firewall`, `tgw`, routing from `edge-dns-routing` and `dr-failover`); a switch promotes Aurora and moves DNS. Its per-cell `eks`, `karpenter`, `iam-workloads` and `memorydb` units keep an `exclude` block only as a fallback switch (`standby.compute_enabled: false` in `config/environments/prod.yaml`); excluding a unit never destroys it. `argocd-standby` lets Argo CD core run in us-east-1 when eu-central-1 is down, and `PAY_STATE_REGION=us-east-1` points every unit at the state replica of `infra/bootstrap`. dev and stage run in eu-central-1 alone; their us-east-1 holds only `panel-edge`, `waf-edge` and a `kms` unit with the `logs` key.
First apply of a root: `infra/bootstrap`, then `tf-exec` with `PAY_TF_DIRECT=true`, `permissions-boundary`, `ci-oidc-roles`; shared-services before the environments (central `eks`, then `argocd-access` hub; each environment's `argocd-access` before its `eks`). Then `tgw`, then set `transit_gateway_id` in `env.hcl` (stage: the region's entry of `deploy.stage.transit_gateway_ids` in `config/platform.yaml`) so that `vpc` routes through it.
Sizes come from `config/environments`: `prod.yaml` is the reference, `dev.yaml` lists what dev lowers, and stage takes the dev sizes of Aurora, MemoryDB and node pools unless `size_window = "prod-size"` in `stage/env.hcl` books a load or failover test window at the prod size (`stage.yaml` then puts the payments and stateful pools on Spot). `env.hcl` merges the file of its environment over `prod.yaml` one level deep. `prod` mirrors `stage` in one account with its own network and zone from `config/platform.yaml`; its node pools never use Spot. `cde-prod` is not a separate account yet: the CDE pool of each cluster is never Spot in any environment.
Analytics (outside the CDE) lives in `<env>/eu-central-1/analytics/`: its own cluster (`eks`, `karpenter`) for ClickHouse, `msk`, `opensearch`, `clickhouse` and the security groups `msk-access` (cell and analytics nodes) and `opensearch-access` (analytics nodes); cell `iam-workloads` attach the MSK producer policy. `ci-oidc-roles` holds the GitHub OIDC plan role of each account (and the ECR read role in shared-services).
