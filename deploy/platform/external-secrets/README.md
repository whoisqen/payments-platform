# External Secrets

External Secrets Operator (2 replicas) with two ClusterSecretStores.

- `values.yaml`: values of the upstream `external-secrets` chart, version `2.15.0`, pinned in `deploy/argocd/templates/addons/external-secrets.yaml`; not vendored (pin lives in the ApplicationSet).
- `config/`: chart `external-secrets-config` with the stores `aws-secrets-manager` (pod identity role, no static keys) and `vault` (Kubernetes auth role `external-secrets`), plus NetworkPolicies with default deny. It is the second source of the ArgoCD Application.
- Per-environment values (`envs/<env>/<region>.yaml`, passed to `config/`) are generated by `tools/config/render_vault.py`: region, Vault address `https://vault.<zone>:8200`, CIDRs. ArgoCD selects the file by the cluster labels `payments-platform/environment` and `/region` and sets `requireResolved=true`. The pod role comes from the EKS Pod Identity association `external-secrets/external-secrets`; `awsSecretsManager.roleArn` stays empty unless a further role is assumed.
- Central cluster (shared-services): `envs/shared-services/eu-central-1.yaml` provides only `aws-secrets-manager` (the store every central ExternalSecret names), limited to the namespaces `monitoring`, `argocd` and `sentry`; Vault is off. Its cluster Secret needs the labels `payments-platform/environment: shared-services` and `payments-platform/region: eu-central-1` besides `addons: enabled`.
- Restrict a store to namespaces with `namespaceSelector`; the CDE cell should select only its own namespaces.
- No secret value is stored here: `ExternalSecret` objects of each cell name keys only.
- Break-glass access to the secrets themselves follows `deploy/platform/vault/README.md`; the operator role has read-only access and no human assumes it.
